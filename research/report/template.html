Super-agent 沒有讓模型更聰明，它重新分配了「誰該讀什麼、誰該等什麼」

傳統 agent loop 是一個上下文、一條同步工具呼叫鏈、一個模型同時負責判斷要不要做與怎麼做。DeepSeek 把它拆成四層：事件源把 IM／GitHub 變成不可變的 Trigger；確定性的 gate 用程式碼決定誰有權發起工作；只做路由的 Router 決定開不開單；每張 Ticket 一個 Worker 在自己的目錄與上下文裡做事。後續訊息靠訂閱直接送到 Worker，不再回頭問 Router。

瓶頸換了文章主張：任務多時，上限來自人的注意力（同時盯 3–5 個 Session），不是模型。所以每個設計都以「少打擾人」為成本函數。
權限搬進程式碼allowlist、admission 表、accept mode、Mandate 都由 host 強制；訊息與文件內容只是資料，prompt injection 改不了它。

架構：兩條路、一個寫入者

新請求走 Eval 路：Trigger → gate → Router 判斷 → 建 Ticket + Mandate → Assignment 給 Worker。既有工作走 訂閱路：Thread 上的新訊息（人的追問、CI、review）直接 fan-out 給訂閱它的 Ticket，Worker 自己判斷範圍。所有決定先寫入 SQLite，再由 Effects 佇列執行，Outbox 用決定性 id 保證同一則回覆只發一次。

領域概念（docs/001）

概念是什麼守的規則
Source事件流（飛書、GitHub）的實作保存讀取位置，重啟不重播；丟掉 bot 自己的訊息；把事件翻成 Thread 與回覆位址
Trigger一個不可變事件同一 Trigger 接受兩次只會產生一張 Ticket（冪等單位）
Thread依時間排序的 Trigger（一個 PR、一個飛書話題）同一 Thread 一次只跑一個 Eval，期間到達的訊息併入下一批
Evalgate（程式碼）+ assessment（模型）兩層判斷不持有狀態；產出 accept / stop / ignore / unavailable
Mandateaccept 授予的權限：Policy 版本、範圍、強度、命中規則不可變；範圍變大要開新單；只有人的 stop 能收回，Policy 不再成立時於 resume 前撤銷
Ticket / Assignment一件被授權的工作 / 綁定到某個 Executor 的一次執行Ticket 自定狀態，不跟隨 Session；可重試、可重啟、可被人的訊息喚醒
SubscriptionTicket 與 Thread 多對多只給上下文，不給權限；被人 stop 的 Ticket 不再收任何訊息

模擬：同一份劇本，三種架構

在本環境裡重建了文章實驗的小型版本。dsh-superagent 一側不是重寫的模型：直接 import repo 的 src/core Engine、settingsPolicy（真的 gate 與 observe 模式）、feishuKind／githubKind 的 scope，接上用 node:sqlite 寫的持久化 Repositories。另外兩個 baseline 是傳統單一 loop（同步執行），以及會把每個請求丟給 subagent 的單 Session（Claude Code 用 Task tool 的形狀）。

為了只比較架構，三者共用同一個 oracle：每則訊息的語意意圖（請求、閒聊、注入、範圍外追問…）事先標好，三種架構讀到的都是「一個能幹模型會得出的判斷」；工作步驟、工具耗時與輸出大小也相同。差異只來自：誰握有哪段上下文、什麼會阻塞什麼、重啟後剩下什麼。

與 Claude 的對照

這次研究本身就是在 Claude Code（雲端 Session）裡完成的，正好拿來對照。Claude Code 是一個強大的單 Session agent：一個上下文、工具同步回傳、可以用 subagent 與背景工作分流。dsh-superagent 是建在 Session 之上的 harness：它不改模型，管的是事件、權限與注意力。

如果要在 Claude 上做 super-agent

Claude 這邊的積木大致都在，缺的是把它們串成「領域模型」的那一層：用 Claude Agent SDK 起一個只帶路由工具的 Router Session 和每單一個 Worker Session；把 gate、Mandate、Ticket 狀態放進資料庫與程式碼（不是 prompt）；用 hook 在工具層擋住 Router 的 sleep 與長等待；用 Outbox 表做冪等回覆。本頁的 research/sim 已經示範了其中最難的部分可以直接複用 DeepSeek 的 src/core，它只依賴 6 個 port（Repositories、Policy、SourceScope、Assessor、Executor、Outbox），模型供應商可換。

反過來說，Claude Code 的單 Session 在「一個人、一個任務、需要深度互動」時更直接：沒有 Router 的轉手與額外 token，人可以即時打斷。super-agent 的優勢只在多來源、多人、多任務、長時間無人值守時才明顯，這與文章自己的數據一致（它用更多 token 換延遲）。

限制與重現

  • 模型判斷是腳本化的 oracle，不是真的 LLM 呼叫；它刻意讓三種架構「一樣聰明」。真實模型在單 Session 裡被注入、忘記上下文、不願委派的機率，這裡沒有算進去。
  • 時間與上下文大小是示意值（每次模型呼叫 6 秒、輸出 400 字元；工具時間見劇本），只跑一次，沒有變異數。Router 與 Worker 的 system prompt 長度取自 repo 真實 prompt 檔，Worker 另加 8k 估計 DSH coding prompt 與 AGENTS.md。
  • baseline 的 Session 歷史在重啟後保留（如 claude --resume），但記憶體中的待處理佇列與進行中的工具呼叫會遺失，之後從聊天紀錄補回。
  • repo 測試在本環境 1197 個中 1196 個通過；失敗的是 tests/sources.spec.ts 的飛書 event consumer 一案（預期 error 狀態卻得到 ready），與模擬用到的 core 無關。
  • 模擬裡觀察到一個原型的真實行為：Alice 在同一飛書話題回答 Ticket C 的問題時，訊息也 fan-out 給同話題的 Ticket A；A 合併結束時把這則「未讀」追問釋放回 Eval，多花一次 Router 判斷（最後 ignore）。同一話題掛多張單時會有這種成本。
